PRODUCT RESEARCH / 03 NOVEMBER 2026

Opportunity, without the ordinary.

A Pakistan-first hiring theme informed by Rozee, Mustakbil and LinkedIn. A distinctive identity, a long discovery homepage and three connected workspaces.

Scope: This is a Next.js frontend theme with browser-local demonstrations. It is not a production recruitment service. Research covers official public product and help pages; paid dashboards were not accessed. Feature availability varies by plan, region and rollout. This is a broad capability inventory, not a claim to have reverse-engineered every system.

02 / Candidate experience

The candidate workspace starts with discovery and a personal application count. Search combines title, company or skill text with city, work arrangement, job type and minimum monthly pay. Sorting supports newest and salary. A vacancy detail dialog keeps the requirements, salary and screening response together. Duplicate active applications are blocked; withdrawing allows a fresh application.

The resume editor separates summary, skills, experience, education, projects, certificates and languages. Printing creates a readable resume through the browser print dialog. Selecting a document remembers only its filename; parsing, secure upload and recruiter delivery are not implemented. Open-to-work and visibility controls are preferences awaiting server enforcement.

Saved searches retain filters and daily or weekly preferences without sending alerts. A skill overlap label explains exact matched keywords; it is not a suitability score or AI prediction. The local network supports outgoing invitation states and a sample incoming acceptance. Feed posts, comments, reactions and company follows demonstrate social interactions without pretending there are real users.

Candidate interview booking, assessment responses and offer interest share local records with the employer view. Interview times are explicitly Pakistan time. Offer interest is nonbinding. Learning, groups, events and newsletters currently collect interests; they do not enroll users, deliver courses or subscribe them externally.

03 / Employer experience

A new vacancy can be saved as Draft or Pending review. An administrator can publish or reject it. Employers can edit descriptions and close roles. Published roles enter candidate search immediately in the same browser. The applicant workspace supports explicit stages, manual ratings and private-note-style fields. The demo role selector is for exploration, not access control: all browser data is accessible to the person using that device.

CV discovery searches fictional profiles and allows adding them to a talent pool. Interview slot creation rejects past dates, zero durations and overlapping intervals. Assessments support a prompt, candidate response and manual review. Offer drafting supports draft, shared, interested and declined states. Production would bind each action to an authenticated employer, candidate and application; the demo uses a single candidate identity.

Team seats, permissions, automation and credits screens capture configuration only. The writing assistant returns a deterministic starter sentence. Hiring analytics show current stage counts and export source records, rather than inventing funnel conversion, time-to-hire or campaign attribution.

04 / Trust, administration and lifecycle

The administration workspace includes vacancy review, a clearly labelled demo employer decision, support case records, a user registry, editorial content and an activity timeline. These are recommended portal capabilities, not claims about competitors' private administrative systems. Browser logs are mutable and cannot serve as compliance evidence.

A production implementation should enforce organization boundaries, separate public and private fields, prevent duplicate submissions transactionally and retain application status events. Job closure should stop applications immediately. Deletion, retention and consent policies must be designed alongside actual data flows. A real verified badge needs a documented review process and evidence, not merely a toggle.

05 / Visual and mobile direction

Vermilion, charcoal and warm ivory distinguish Hirestaff from generic blue job boards. Large editorial headlines contrast with compact functional cards. The existing long homepage remains the public discovery surface; the workspace uses denser layouts suited to repeat visits. On phones, persistent bottom tabs expose common tasks and a drawer contains the full role navigation. Cards become a single column, inputs retain readable text sizes, and job details use a native modal with a compact mobile presentation.

The Next.js build exports static pages and uses local assets, avoiding a component framework and third-party tracking scripts. The public homepage and workspace are separate routes. This is a web app-style interface, not a native app. Offline support, service workers, push permissions, an install lifecycle and store distribution are additional work. Performance targets should be measured on representative Pakistani mobile connections and low-end devices; no Lighthouse score is claimed.

06 / Production architecture

Core records: users, organizations, memberships, candidate profiles, resumes, jobs, questions, applications, application events, reviews, interview slots, bookings, assessment assignments, answers, offers, messages, connection requests, follows, posts, moderation cases, purchases and audit events. Every private record needs an owner or tenant identifier.

Application boundary: replace local storage with authenticated server endpoints. Treat role selection as a demo-only control. Enforce authorization at each operation, not in navigation. Use database constraints for active application uniqueness and concurrent booking. Store documents privately with short-lived access URLs and validation. Use an event queue for notifications and scheduled work, with retries and idempotency keys.

External services: identity provider, private storage, email and push, calendar connection, search index, payment processor and signature provider. AI features need documented inputs, consent, evaluation, explanations and human decisions. No model should silently reject applicants based on inferred sensitive traits.

Search visibility: replace hash-only workspace navigation with appropriate authenticated routes when needed. Give public jobs stable indexable URLs, actual publishing/expiry dates and valid JobPosting schema. Generate a sitemap and remove expired vacancies from active search. The current demo intentionally remains noindex.

07 / Delivery sequence and acceptance gates

  1. Core launch: authentication, organizations, profiles, private CVs, job moderation, search and transactional applications. Verify cross-account isolation and closed-job handling.
  2. Recruitment operations: stage history, real messages, interview calendars, assessments and offer documents. Verify timezone behavior, race conditions and notification delivery.
  3. Discovery and revenue: company publishing, consent-based resume discovery, billing, credits and promoted jobs. Verify payment webhooks and prevent double charges or double contact deductions.
  4. Professional community: mutual connections, feed moderation, reports, blocks, events and newsletters. Establish abuse handling and delivery preferences before enabling distribution.
  5. Intelligence: evaluate matching and drafting with representative Pakistan job data; measure quality rather than presenting arbitrary match percentages.
